# Security & Implementation Patterns

Use these controls to run Google Analytics-backed MCP tools safely in production. The primary goals are to protect service account credentials, keep GA4 property access scoped, and prevent unnecessary or unintended API calls.

## Guardrails & Restricted Operations

Restrict each integration instance to a single GA4 property. Avoid configuring the tool with a service account that has access to multiple properties unless your use case explicitly requires it.

:::danger Service Account Key Exposure Risk
A leaked service account JSON key grants immediate read access to all GA4 properties the account is linked to. Treat this file with the same sensitivity as a database password. If you suspect a key has been exposed, revoke it immediately in [Google Cloud Console → Service Accounts](https://console.cloud.google.com/iam-admin/serviceaccounts) and issue a new key.
:::

## Security Best Practices

- **Use the Viewer role only.** This integration requires read-only access to GA4 data. Assigning Editor or Administrator roles to the service account grants unnecessary privileges that could be exploited if credentials are compromised.
- **Rotate keys on a schedule.** Create a new service account JSON key periodically and revoke the old one. Most organizations rotate credentials every 90 days. Then replace you json in MCP Express aswell.
- **Revoke compromised keys immediately.** If a key is accidentally exposed — in a log, a commit, or a support ticket — delete it from [Service Account Keys](https://console.cloud.google.com/iam-admin/serviceaccounts) before issuing a replacement.
- **One service account per integration.** Do not reuse the same service account across multiple systems. Isolated accounts make it easier to audit access and revoke a single account without affecting other services.

## Dynamic vs. Fixed Configurations

- **Fixed Property Context**: Bind the integration to a single Property ID. This limits the scope of any accidental misconfiguration to one property and simplifies auditing.
- **Bounded Result Limits**: Set explicit result limits on actions that support them (Get Top Pages, Get Top Events, Get Landing Pages, Get User Demographics). Unbounded queries can increase API response times and consume quota faster.

:::warning Quota and Rate Limits
The Google Analytics Data API enforces [daily quota limits](https://developers.google.com/analytics/devguides/reporting/data/v1/quotas). High-frequency polling or very large result sets can exhaust your quota. Keep result limits reasonable and avoid scheduling the tool to run continuously without delay.
:::

## Troubleshooting

Use the table below to diagnose and resolve errors returned by the integration.

| Error                                                  | Likely Cause                                                              | Resolution                                                                                                                                                                                                                                    |
| ------------------------------------------------------ | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Validation error: Action is required                   | The action field was not provided in the tool configuration.              | Open the tool configuration and set the Action field to one of the supported values (e.g. Get Active Users).                                                                                                                                  |
| Validation error: Start date and end date are required | A date-range action was called without Start Date or End Date.            | Provide both Start Date and End Date. Both fields must be non-empty strings in `YYYY-MM-DD` format.                                                                                                                                           |
| Validation error: Service Account JSON is required     | The Service Account JSON field is empty or missing.                       | Paste the full content of your service account JSON key file into the Service Account JSON field.                                                                                                                                             |
| GA4 API error: Permission denied                       | The service account does not have access to the GA4 property.             | Go to GA4 Admin → Property Access Management and confirm the service account email is listed with at least Viewer access. See [Integration](/docs/integrations/google-analytics/integration#step-5--grant-the-service-account-access-in-ga4). |
| GA4 API error: Property not found                      | The Property ID is incorrect or does not match the authenticated account. | Verify the Property ID in GA4 Admin → Property Settings. Confirm the service account has been added to that specific property.                                                                                                                |
| GA4 API error: Quota exceeded                          | Your Google Analytics Data API quota for the day has been exhausted.      | Wait until the quota resets (typically midnight Pacific Time) or apply for a quota increase via [Google Cloud Console](https://console.cloud.google.com/apis/api/analyticsdata.googleapis.com/quotas).                                        |
| GA4 API error: Request timed out                       | The API did not respond within the configured Request Timeout window.     | Increase the Request Timeout field to a higher value (e.g. `60`) and retry. If timeouts persist, check whether the query spans an unusually large date range.                                                                                 |
| Network error connecting to GA4 API                    | MCP Express could not reach the Google Analytics Data API endpoint.       | Verify that outbound HTTPS connections to `analyticsdata.googleapis.com` are allowed in your network or firewall settings.                                                                                                                    |

## Protocol Limitations

- The Google Analytics Data API is read-only. This integration cannot modify GA4 property settings, events, goals, or audiences.
- Real-time data (Get Realtime Users) reflects a short rolling window and is not suitable for historical analysis.
- City-level demographic data may be sparse for properties with low traffic volume due to GA4's data thresholds and privacy protections.
- GA4 properties do not contain historical data from before the measurement ID was first implemented.
