# Configuration

Once your Google Cloud service account is set up and linked to your GA4 property, configure which reporting action the tool performs and which parameters are supplied at runtime. Every action shares the same base connection fields; additional fields vary by action.

## Action Configuration

Use action configuration to select which GA4 report the tool runs and to supply the required date ranges, limits, or dimension preferences.

### Supported Actions

The following actions are available in the Google Analytics integration:

- **Get Active Users**: Retrieve session and user activity over a date range.
- **Get Top Pages**: List the most visited pages on your site or app.
- **Get Traffic Sources**: Break down sessions by acquisition channel, source, and medium.
- **Get Realtime Users**: View live visitor counts — no date range needed.
- **Get Top Events**: See which GA4 events fire most often.
- **Get User Demographics**: Segment active users by country, city, or language.
- **Get Device Breakdown**: See how users are distributed across device types, operating systems, and browsers.
- **Get Landing Pages**: Identify which pages users land on first and how they perform.
- **Get Conversions**: Analyze conversion events by event name and acquisition channel.
- **Compare Date Ranges**: Place two time periods side by side to compare key metrics.

---

## Common Configuration Fields

All actions require the following base fields. These are supplied once per integration instance and apply to every action.

| Field                | Description                                                                                                                              | Required |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Action               | The reporting action to run (e.g. `Get Active Users`). Always required.                                                                  | Yes      |
| Service Account JSON | Full content of the Google service account JSON key. See [Integration](/docs/integrations/google-analytics/integration) for setup steps. | Yes      |
| Property ID          | GA4 property identifier. Accepted as a plain number or in `properties/123456789` format.                                                 | Yes      |

## Action Reference

### Get Active Users

Returns daily session and user metrics — total sessions, active users, and new users — across the specified date range. Use this to track overall traffic trends over time.

| Field      | Description                                            | Required |
| ---------- | ------------------------------------------------------ | -------- |
| Start Date | Beginning of the reporting window (e.g. `2024-01-01`). | Yes      |
| End Date   | End of the reporting window (e.g. `2024-01-31`).       | Yes      |

**What it reports:** Daily breakdown of `Sessions`, `Active Users`, and `New Users` grouped by date.

**Common failure:** If you receive a validation error about missing dates, make sure both Start Date and End Date are provided and non-empty.

---

### Get Top Pages

Returns a ranked list of your most-visited pages, including page views, average session duration, and bounce rate. Useful for identifying high-traffic content.

| Field        | Description                                                     | Required |
| ------------ | --------------------------------------------------------------- | -------- |
| Start Date   | Beginning of the reporting window.                              | Yes      |
| End Date     | End of the reporting window.                                    | Yes      |
| Result Limit | Maximum number of pages to return. Default: `10`. Minimum: `1`. | No       |

**What it reports:** Page path, page title, `Page Views`, `Average Session Duration`, and `Bounce Rate` for the top pages.

**Common failure:** If bounce rate values seem unexpectedly low, check whether your GA4 property has session engagement configured correctly. GA4 uses engaged sessions, which affects bounce rate calculation differently from Universal Analytics.

---

### Get Traffic Sources

Shows how users arrive at your site or app, broken down by default channel group (e.g. Organic Search, Direct, Referral), source, and medium. Useful for evaluating marketing channel effectiveness.

| Field      | Description                        | Required |
| ---------- | ---------------------------------- | -------- |
| Start Date | Beginning of the reporting window. | Yes      |
| End Date   | End of the reporting window.       | Yes      |

**What it reports:** `Sessions`, `Active Users`, and `Conversions` grouped by channel group, source, and medium.

**Common failure:** If organic or paid channels appear empty, verify that your GA4 property has the relevant traffic sources configured and that the date range covers a period with recorded sessions.

---

### Get Realtime Users

Returns live visitor counts currently active on your site or app. No date range is required. Use this as your first validation call after setting up the integration.

This action has no additional fields beyond the base configuration.

**What it reports:** `Active Users` broken down by country, device category, and active screen or page name.

**Common failure:** If the result shows zero active users but you expect traffic, confirm that the correct property is configured. Real-time data is only available for properties with active sessions at the time of the query.

---

### Get Top Events

Lists the GA4 events that fire most frequently within the date range, along with how often each event fires per user.

| Field        | Description                                                      | Required |
| ------------ | ---------------------------------------------------------------- | -------- |
| Start Date   | Beginning of the reporting window.                               | Yes      |
| End Date     | End of the reporting window.                                     | Yes      |
| Result Limit | Maximum number of events to return. Default: `10`. Minimum: `1`. | No       |

**What it reports:** `Event Count`, `Event Count Per User`, and `Total Users` grouped by event name.

**Common failure:** If expected events are missing, verify they are tracked in your GA4 implementation and that the date range includes days when the events fired.

---

### Get User Demographics

Segments active users and sessions by a single geographic or language dimension. Use this to understand where your audience is located or what languages they use.

| Field               | Description                                                                                                  | Required |
| ------------------- | ------------------------------------------------------------------------------------------------------------ | -------- |
| Start Date          | Beginning of the reporting window.                                                                           | Yes      |
| End Date            | End of the reporting window.                                                                                 | Yes      |
| Breakdown Dimension | Which dimension to group by. Options: `Country`, `City`, `Language`. Defaults to `Country` if not specified. | No       |
| Result Limit        | Maximum number of rows to return. Default: `10`. Minimum: `1`.                                               | No       |

**What it reports:** `Active Users` and `Sessions` grouped by the selected dimension.

**Common failure:** If city data appears sparse, this is normal — city-level data requires sufficient traffic volume for GA4 to record and report it accurately.

---

### Get Device Breakdown

Shows how users are distributed across device types (desktop, mobile, tablet), operating systems, and browsers. Use this to inform responsive design and cross-platform decisions.

| Field      | Description                        | Required |
| ---------- | ---------------------------------- | -------- |
| Start Date | Beginning of the reporting window. | Yes      |
| End Date   | End of the reporting window.       | Yes      |

**What it reports:** `Active Users`, `Sessions`, and `Bounce Rate` grouped by device category, operating system, and browser.

**Common failure:** If mobile data looks unexpectedly low, check whether your GA4 tracking code is installed on mobile views and that the measurement ID is the same across all surfaces.

---

### Get Landing Pages

Identifies the pages where users begin their sessions, along with session volume, bounce rate, and conversions generated from each landing page.

| Field        | Description                                                             | Required |
| ------------ | ----------------------------------------------------------------------- | -------- |
| Start Date   | Beginning of the reporting window.                                      | Yes      |
| End Date     | End of the reporting window.                                            | Yes      |
| Result Limit | Maximum number of landing pages to return. Default: `10`. Minimum: `1`. | No       |

**What it reports:** `Sessions`, `Bounce Rate`, and `Conversions` grouped by landing page path.

**Common failure:** If your top landing pages are not appearing, verify that your GA4 property has session data within the selected date range and that landing page tracking is not filtered by any view or data stream filter.

---

### Get Conversions

Reports on conversion events by event name and acquisition channel. Use this to see which events count as conversions and which marketing channels drive them.

| Field      | Description                        | Required |
| ---------- | ---------------------------------- | -------- |
| Start Date | Beginning of the reporting window. | Yes      |
| End Date   | End of the reporting window.       | Yes      |

**What it reports:** `Conversions`, `Total Users`, and `Sessions` grouped by event name and default channel group.

**Common failure:** If conversion counts are all zero, verify that your GA4 property has conversion events configured. In GA4, events must be explicitly marked as conversions in **Admin → Events** before they appear in conversion reports.

---

### Compare Date Ranges

Places two separate date ranges side by side and compares sessions, active users, page views, and conversions between them. Use this for period-over-period analysis such as month-over-month or year-over-year comparisons.

| Field                   | Description                                  | Required |
| ----------------------- | -------------------------------------------- | -------- |
| First Range Start Date  | Start date for the first comparison period.  | Yes      |
| First Range End Date    | End date for the first comparison period.    | Yes      |
| Second Range Start Date | Start date for the second comparison period. | Yes      |
| Second Range End Date   | End date for the second comparison period.   | Yes      |

**What it reports:** `Sessions`, `Active Users`, `Page Views`, and `Conversions` broken down by date for each period, allowing direct comparison.

**Common failure:** If one period returns no data, check that the property had tracking active during that period. Newly created GA4 properties do not have historical data before the measurement ID was implemented.

---

## Governance Controls

- Supply the Service Account JSON through a secrets vault or environment variable — never hardcode it in the tool configuration.
- Restrict each integration instance to a single GA4 property. Do not share one integration across multiple properties.
- Use the Result Limit field to keep response sizes manageable. Large result sets can increase latency.

:::tip Test Before Deploying
Use the built-in testing utility to verify that all required fields resolve correctly, that the service account has property access, and that the action returns data before enabling the tool in production.
:::
