# Security & Implementation Patterns

This section outlines the protocols and guardrails that keep SFTP integrations secure, predictable, and compliant with enterprise governance standards.

## Guardrails & Restricted Operations
SFTP tools can access arbitrary file paths if inputs are not constrained. Restrict operations to approved base directories and limit write-capable actions to controlled paths.

:::danger Path Scope Must Be Enforced
Unvalidated `remote_path` or `remote_file_path` values can expose sensitive directories. Treat all Jinja2 inputs as untrusted and enforce allowlists or prefix checks.
:::

## Authentication Hardening
- Prefer key-based authentication over passwords for production environments.
- Store private keys in a secure location with permissions set to 600.
- Use a dedicated service account with access limited to required directories.

## Data Governance & Scopes
- Reject relative path traversal sequences such as `../`.
- Separate inbound upload directories from outbound download paths.
- Audit operation metadata (action, user, path) to support traceability.
- Disable recursive operations on unknown directory trees.

## Performance Optimization

| Pattern | Description | Benefit |
| --- | --- | --- |
| Bounded Results | Keep `max_results` conservative for search and list operations. | Prevents oversized responses. |
| Limited Recursion | Recursive search and list are capped in depth. | Avoids runaway traversal. |
| Targeted Patterns | Use narrow patterns instead of broad wildcards. | Reduces scan time. |
| File Size Controls | Avoid returning very large files inline. | Protects response latency. |

## Protocol Limitations
- Binary content is returned as base64 when `encoding` is set to `binary` or when auto-detection fails.
- Very large files can exceed response size limits if returned inline.
- Deep directory traversal can exceed operational timeouts.
